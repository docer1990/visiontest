# VisionTest 1.0.0

VisionTest 1.0.0 adds sequential CLI flows, screen recording, compact inspection,
and structured action results to the Android and iOS automation tools. This
release also adds opt-in performance tracing and updates the project-local agent
skill with a CLI-first testing workflow.

## Highlights since 0.2.0

- Run known action sequences in one process with `flow`, using repeated `--step`,
  a file, or stdin. Arguments are validated before device access. Flows stop on
  the first failure and can collect final observations or bounded failure evidence.
- Add `flow --record` to require a validated screen video on Android or an iOS
  simulator. Reports include recording status and the saved host path. Recording
  failures make the flow unsuccessful while preserving an earlier step failure.
- Request compact interactive-element results through CLI, MCP, or flow
  observations, with optional native type, region, and bounds controls.
- Use `--json` with all 14 standalone UI interaction commands. Appearance and
  disappearance waits now provide symmetric text output and optional structured
  results with `condition` and `satisfied` fields.
- Collect local host and optional native performance timing through
  `--trace-performance` for CLI or `VISIONTEST_TRACE_PERFORMANCE` for MCP.
  Reproducible benchmark tooling and native fixture apps support measurement.
- Refresh the generated agent skill for concise CLI-first inspection, action,
  verification, and recovery guidance.

## Upgrade

Re-run the [installer](../installation.md) to upgrade the JAR, Android APKs, and,
on supported Macs, the iOS bundle. Stop running automation servers before replacing
their native artifacts. On Android, run
`visiontest install_automation_server -p android` to install both updated APKs on
the device, then restart the server. Restart the iOS server with the updated bundle.
The JAR and Android version name are `1.0.0`; Android's version code is `3`.

Run `visiontest init --agent <agents>` in each project to refresh its generated
skill. Init replaces the selected skill files completely, so save any local edits
before running it.

Scripts parsing wait text should accept `Element appeared.` and `Element gone.`,
or use `--json`. For standalone commands, exit 0 still means the command returned
normally, including returned operation failures. Inspect `success`, `found`, or
`error` as appropriate. A wait's `satisfied` field alone does not establish an
error-free result. Flow exit 0 instead requires successful steps, all requested
final observations, and a valid recording when `--record` is requested.

## Operating limits

Flows do not roll back, replay, or automatically retry actions. If an action's
outcome is uncertain after response loss or a timeout, inspect the current UI
before retrying. Recording captures the whole display without audio. Configure
the automation backend and recorder for the same isolated device or simulator;
there is no runtime backend identity check.

Device commands require `--platform android|ios`. Generic iOS text clearing and
explicit CLI selection among multiple attached devices remain unavailable. The
prebuilt iOS bundle requires macOS arm64 and a compatible full Xcode installation;
Intel Macs require a source build for iOS automation.
