# Release 0.2.0 preparation

## Scope

The release audit identified incorrect wait validation, gaps in the distributed
agent skill, and stale release versions. The user approved fixing these on a new
branch and will publish after the Android smoke test passes. Publication, merging,
and unrelated backlog features are outside this change.

## Behavior

CLI waits validate selectors, timeout, and platform-specific app scope before
creating device components. Invalid input exits 2 even when the server is down.
Android rejects `--bundle-id`; iOS scope must be nonblank and cannot replace an
element selector. Shared wait registrars validate before checking server health,
so MCP and CLI preserve the same validation order. Valid waits retain existing
polling, output, timeout, and transport-failure semantics.

Init continues to write one self-contained skill offline for Claude, OpenCode,
and Codex. The generated Markdown identifies the runtime VisionTest version
through the existing `VersionInfo` source. Reinitialization replaces the complete
file deterministically. The skill explains refresh and overwrite behavior,
CLI/MCP discovery, native server upgrades, iOS prerequisites, device selection
limits, iOS selector precedence, text replacement limits, and opening screenshots
before visual judgments. A short worked flow demonstrates actual outcome checks.
It keeps essential interaction and failure contracts without duplicating all help.

The JAR and Android version name become 0.2.0. The Android version code increases
to 2. Release notes describe changes since 0.1.2 and migration for the CLI,
native servers, and project-local skills. The release guide requires a passing
Android smoke run for the intended release commit and documents how to run it
for a branch. The existing SDK setup correction remains unchanged.

## Verification

Use existing JUnit tests with TDD, including CLI tests that fail if lazy components
are initialized on invalid input and registrar tests that observe zero backend
requests. No new BDD framework is needed; existing Markdown contracts describe
the public scenarios. Test generated version provenance against the packaged
JAR manifest, deterministic overwrite, and identical content for all agents.
Use the audit's six simulated agent scenarios as the skill baseline and repeat
them independently after the revision. They do not substitute for device tests.

Run `./gradlew :app:test`, `./gradlew :app:e2eTest`, `./gradlew build`, and
`git diff --check`. Native code is unchanged. The next Android smoke run remains
the final external release gate. Preserve the branch for the user's release.
